## 2026-06-04: SpaceFL 实验系统 + 性能优化 + 太空实验设计

### 代码优化
1. **并行客户端训练** (`server.py`): 新增 `_train_clients_parallel()` 方法，使用 `ThreadPoolExecutor`，由 `num_train_workers` 控制并行度。GPU训练场景下CUDA释放GIL，多线程可重叠计算。`FLConfig` 新增 `num_train_workers` 字段。
2. **DataLoader workers** (`runner.py`): 新增 `num_workers` 参数传入 DataLoader，支持 `pin_memory=True`（GPU场景自动启用）。`FLConfig` 新增 `num_workers` 字段。

4. **标准FL基线**: `runner.py` 中 `scheduler=None` 即可模拟无轨道约束的标准FL（始终可通信）。

### 动态模拟时间 (2026-06-04 晚)
- **问题**: `sim_hours` 原本是硬上限——预计算固定数量的 timeslot，超出后训练终止

  - `OrbitSimulator._extend_to()` / `_compute_contacts_for_slot()`: 按需计算超范围 timeslot

### 关键Bug修复 (2026-06-04 晚)
**Bug 1 — 聚合永不触发（SpaceFL准确率锁死7%）**：
- 根因: `SyncWeightedAggregator.min_updates = max(1, min_clients) = 10`，SpaceFL下每轮仅2-3个update，`should_aggregate()` 永远返回False，全局模型从未更新
- 修复: `min_updates` 改为默认1（同步FL中收到的update数=实际参与客户端数，无需额外门槛）
- 影响文件: `fedavg.py`, `fedprox.py`

**Bug 2 — 基线/SpaceFL组件创建混用**：
- 修复: 实验脚本中分离两种模式——基线用 `min_clients=num_clients`，SpaceFL用 `min_clients=1`
- 影响文件: `examples/run_spacefl_experiment.py`

**Bug 3 — torch.manual_seed 未设置**：
- 模型初始化非确定性（每次运行权重不同）
- 修复: `runner.py` 中模型创建前设置 `torch.manual_seed(config.seed)`

**性能优化**：
- 串行训练路径：`global_weights` 从每客户端克隆改为每轮克隆一次（3客户端节省2次clone）

### non-IID 数据分配修复 (2026-06-04 深夜)
- **问题**: 实验脚本硬编码 `iid=True`，每颗卫星都拿到全10类数字的全量数据，2个客户端就能达到86%准确率，完全体现不出FL的价值
- **修复**: 
  - 默认改为 `iid=False, alpha=0.3` (Dirichlet non-IID，每颗卫星偏斜拿到2-3个主导数字类)
  - `quick_test.py` / `run_spacefl_experiment()` / `run_baseline_fl()` / `run_experiment_suite()` 全部支持 iid/alpha 参数
  - CLI 新增 `--iid` 和 `--alpha` 参数
- **影响文件**: `examples/quick_test.py`, `examples/run_spacefl_experiment.py`

### FedProx准确率震荡分析 + 结果自动保存 (2026-06-05 凌晨)
- **300轮实验完成**: 5GS×10异构卫星×2类/卫星, FedProx μ=0.01, 最终acc=0.5864, max=0.8852@R173
- **核心问题**: 准确率剧烈震荡(0.15-0.89), 根因链:
  1. 2类/卫星 extreme non-IID → 每颗卫星知识面极窄
  2. 轨道约束下部分轮次仅1-2颗在线 → 聚合器被少数客户端主导
  3. `SyncWeightedAggregator` 按data_size加权 → 1个客户端=100%聚合权重
  4. FedProx μ=0.01 太弱 → 不足以阻止单客户端漂移
- **数据验证**: 1客户端在线 → acc~0.20-0.35; 4-5客户端 → acc~0.75-0.88
- **修复方向**: (1) 增大μ到0.1-1.0 (2) 自适应μ=base_μ/num_selected (3) 聚合器按类归一化
- **quick_test.py 重大升级**: 自动保存results/目录 (experiment_config.json + experiment_results.json + accuracy_curve.png + contact_heatmap.png + gs_map.png), 支持 --mu/--gs/--output 等CLI参数
- **新增**: `examples/parse_log.py` 日志解析工具 (终端输出→JSON)

### FedProxSat: 准确率感知自适应 μ (2026-06-05 凌晨)
- **需求**: 保留用户设定 μ 的权利，同时根据准确率震荡自动调整 μ
- **实现** (`fedprox.py`):
  - `AdaptiveProximalTrainer(ProximalTrainer)`: 维护最近 N 轮准确率滑动窗口
  - `update_accuracy(acc)`: 每轮评估后服务器调用
  - 震荡逻辑: 窗口max-min ≥ 0.1 → μ↑ (因子1-10x), < 0.03 → μ↓ (0.8x衰减)
  - `mu_stats` 属性返回当前 μ、窗口、震荡值
- **server.py**: 评估后调用 `trainer.update_accuracy(current_acc)` (hasattr 检测，非侵入)
- **quick_test.py CLI**: `--mu`(基础μ), `--mu-min/--mu-max`(自适应边界), `--no-adaptive`(切换传统FedProx), `--oscillation-threshold/--stability-threshold`(阈值)
- 默认使用 FedProxSat 自适应模式
