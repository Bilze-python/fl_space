# SpaceFL 动态通信、抗干扰与链路竞争：文献证据和实现规范

调研日期：2026-11-11。状态：设计提案，尚未实现。本文只新增研究与设计资料，不改变训练器和公网部署。

## 1. 结论与范围

相关研究充分存在，可支持将当前“可见窗口 + 固定带宽/解析时延”扩展为“动态链路 + 干扰计算 + 共享资源调度 + 真实交付事件”。最适合本项目的第一版，是在现有轨道与 FL 之间增加独立通信仿真层，先实现可验证的物理和队列基线，再比较抗干扰策略。

必须区分以下问题：

| 问题 | 成因与接收端 | 建模方式 | 本期定位 |
| --- | --- | --- | --- |
| 同频/邻频干扰 | 其他合法发射机在目标接收机形成干扰 | 方向图、路径损耗、频谱重叠、同时发送集合 | 核心 |
| 恶意干扰 | 外部干扰源向目标接收机注入额外功率 | 发射位置与时序、频谱、接收端干扰功率 | 核心，纯软件仿真 |
| 资源竞争 | 多个流争用带宽、波束、终端或地面站 | 分配、队列、接入、ACK、重传 | 核心 |
| 非预期电磁辐射 UEMR | 星载设备辐射影响地面射电观测 | 频段相关的功率谱密度与接收天线 | 真实干扰存在的证据；第一版不做射电天文复现 |
| 光通信扰动 | 指向误差、捕获/跟踪失败、接收光背景等 | 独立光学信道与终端模型 | 第二阶段；不套用 RF 同频干扰参数 |

这些论文包含星地链路和星载干扰源研究，但不是每篇都研究星间通信。射电观测证明卫星可能产生真实干扰，不能据此直接推出 Ku/Ka 波段通信丢包率或光链路性能。

### 2.2 两个应避免照搬的细节

1. [3] 摘要“approximately 97%”容易被误写成绝对成功率；正文 p.12 明确为 **97% of CTE's convergence performance**，本方案采用正文口径。
2. [4] pp.13–15 一方面描述 GEO 高度约 **35,786 km**，另一方面给出单程传播延迟约 **59–61 ms**。按 `d/c`，仅高度对应的最短单程延迟就约 **119.37 ms**，地面斜距只会更长。原文未在本次核读位置解释这个差异。保留其报告的算法数值作为论文结论，但不把该时延配置用于 SpaceFL 的物理校准。

## 3. 现有项目接口与架构选择

现有 `fl_space/isl/base.py` 的 `ISLWindow` 表达可见窗口与距离；`fl_space/simulator/contact_matrix.py` 表达接触关系；`fl_space/fl/time_model.py` 的 `PhysicsTimeModel` 可按模型大小估计上传/下载时长；`fl_space/fedleo/metrics.py` 提供按带宽计算卸载耗时的函数。局部星簇仍为解析式结果。这些能力可复用，但不足以表示多个传输同时占用同一接收机、排队以及逐段交付。

## 4. 物理和通信模型规范

### 4.1 动态链路

每条链路明确 `rf_ground_uplink`、`rf_ground_downlink`、`rf_isl` 或 `optical_isl`。收发方向独立计算，不因 A→B 可用就默认 B→A 等速可用。

每步由轨道给出位置、速度、斜距、视线和仰角；RF 模型至少计算自由空间损耗、收发方向增益、噪声与其他损耗。星地天气/大气可插拔，第一版可采用明确标注的晴空假设；星间真空路径不添加雨衰。轨道后端 `kepler` 或 `sgp4`、通信模型 `first_order` 分别记录，SGP4 不等于高保真通信。

```text
FSPL_dB = 20 log10(4π d_m f_hz / c_mps)
Pr_dBW  = Pt_dBW + Gt_dBi + Gr_dBi - FSPL_dB - L_other_dB
N_W     = k_B T_system_K B_hz
SINR    = S_W / (N_W + I_legal_W + J_external_W)
delay_propagation_s = d_m / c_mps
f_d_hz = -(range_rate_mps / c_mps) × carrier_hz
```

`T_system_K` 必须声明参考面与包含项；若由天线温度和接收机噪声系数换算，不能再重复计入同一噪声。dB/dBW/dBm 只用于表示，多个干扰源求和必须先转换为 W。EIRP 已包含发射天线增益；使用 EIRP 时不得再次加 `Gt`。[5] 的 EIRP 单位是 dBW/Hz，必须按实际占用带宽积分后才可用于功率预算。

第一版允许 `ideal_upper_bound` 使用 `B log2(1+SINR)`，界面和结果必须写明 Shannon 上界。工程曲线用有来源的 MCS/BLER 或包错率表；编码、包长、残余频偏和适用范围一起归档。不能把理论容量当实测净吞吐。

多普勒分为可预测补偿项和残余误差。先实现补偿后的残余损耗/失锁门限模型；未经校准不凭空把全部多普勒直接当衰减，也不因换频就假定零同步成本。

### 4.2 干扰与抗干扰

干扰贡献对每个接收机单独计算：

```text
I_rx_W = ∑ integral(PSD_j_at_receiver(f,t) × receiver_filter(f), df)
```

平坦谱近似才可写成“总接收干扰功率 × 频谱重叠比例”，比例分母必须取干扰源占用带宽并注明滤波假设。合法发送集合由当步资源分配确定；调度后重新计算相互 SINR，未实际发送的候选链路不产生干扰。

第一版软件场景支持 `none / fixed_band / sweep / stochastic_markov`。每个过程记录活动时间、占空比、频谱和位置；固定总干扰功率与固定 PSD 是不同对照条件，不能混用。可用接收端归一化 J/S 做敏感性扫描，但要标为抽象压力测试，不能宣称对应现实发射装备参数。

防御基线按复杂度递增：固定信道、随机选频、基于延迟测量的避扰换频、功率受限自适应、换星/换路由；后续才引入 DQN/VDN。功率策略遵守每终端及整星预算，功率提高必须支付能耗，所有策略记录感知、信令、换频、捕获和重同步时间。[4] 的结果提示这些成本不应忽略。

策略只能读取当前/历史可获得的测量。真实信道和未来干扰轨迹放在引擎私有状态，`Observation` 必须有测量时间和延迟；Oracle 只作为单列上界。若后续加入响应式干扰，触发应依赖已发生的感知并带反应延迟，不能先看同一时刻尚未发出的动作。

RF 干扰不直接降低光 ISL。光学通道需另建接收光功率、指向/抖动、捕获跟踪、视场/背景光模型；本次 RF 文献不提供其定量抗扰参数。跨类型路由允许绕行，但仍受光终端数量与获取时间限制。

### 4.3 链路竞争、队列和交付

第一版同时提供两种互斥接入口径：

- **调度式接入**：固定帧 TDMA、轮询和 DRR 基线；资源单元为频段/时隙/波束/终端，正交资源不额外制造碰撞。
- **竞争式接入**：Slotted ALOHA，固定时隙与随机退避；默认碰撞模型中同槽多包失败。后续启用 SINR capture 或 CRDSA/SIC 时必须显式切换，不能既判“全部碰撞失败”又声称进行了成功捕获。

CRDSA/IRSA 是后续可选协议，不等同于简单重传。实现时需建模副本占用资源、关联标识、缓冲帧、SIC 迭代与残差，理想 SIC 必须标注。用 [6] 的理想场景作独立验证，不能要求带有现实噪声的生产配置精确得到 0.486 packet/slot。

硬约束至少包括：整星总功率、终端 RF 带宽、半双工/全双工能力、每星并行终端/波束数、地面站并发容量、每个终端的捕获占用、队列容量。全连接拓扑只是候选连接；若只有一个终端，不能同时发送到所有邻星。

每条消息记录模型版本、字节数、截止时间、优先级和接收方。先选路和排队，再分片发送，随后传播、解码和 ACK；每个分片只能处于一个明确状态。模型只有完整交付后才能产生聚合事件。链路中断后可续传或重启，策略写入配置；重传占用真实发送容量并计入能量，ACK 也有传播及资源成本。

`delivered_payload_bytes` 只数唯一有效交付载荷，`air_bytes` 包括头部、编码、副本和重传。不能将重传流量算成有效吞吐。传输可靠率已通过包事件采样时，不再对已交付字节重复乘一次成功率。

消息延迟分解为排队、资源等待、发送、传播、同步/重连和重传等阶段。并发阶段按事件关键路径计算；多个并行发送的耗时不能简单求和，也不能对同一传播等待重复计费。

## 5. 时间轴、数据契约与 FL 接入

轨道采样、MAC 时隙、包事件和训练轮次分别表示。建议起步轨道采样 1 s、MAC 时隙 10 ms，均为**工程初值，非论文结论**；对快速切换/干扰事件细化到事件边界。分钟级现有 FL timeslot 不足以表示毫秒接入和秒级切换。[5] 使用 0.1 s 仿真分辨率、15 s 切换，只作为其场景参数。

采用整数微秒或纳秒事件时间，输出秒；同一时刻用稳定事件序号保证可重复。几何插值仍需复核地球遮挡和可见性边界。步长减半时关键结果变化超过预定容差，应继续细化，不能仅调整显示帧率。

建议公开接口（提议名称）：

```python
engine.submit(TransferRequest(...)) -> transfer_id
engine.advance(until_time_s) -> list[TransferEvent]
engine.observe(node_id, at_time_s) -> Observation
policy.allocate(observation, pending_requests) -> Allocation
engine.export_trace() -> CommunicationTrace
```

`CommunicationConfig`、`RadioTerminal`、`LinkState`、`TransferRequest`、`Allocation`、`TransferEvent` 使用 dataclass，提供 `to_dict/from_dict` 和合法性校验。日志至少包含时间、链路/流/节点 ID、频段、分配资源、SINR/INR、有效速率、排队长度、重传次数、阻塞原因、完成状态和模型版本。配置、轨道快照、模型参数来源、代码版本、各随机流 seed 与策略训练 checkpoint 一起保存。

FL 适配分两步：

1. **通信回放阶段**：以固定模型更新大小和生成时间产生消息，验证网络指标。这一阶段不得绘制“真实训练准确率提升”。
2. **真实 FL 阶段**：以实际模型序列化大小提交下载/上传/卸载请求。`fl/server.py` 收到完整交付事件后再将更新纳入聚合；同步、异步和过期丢弃分别沿用明确算法规则。启用新引擎后，旧 `PhysicsTimeModel` 不再额外计算同一段上传/下载耗时，保留计算训练时间和显示适配。

`FedLEO` 的样本卸载与模型聚合必须分别记账。转移样本仍保持样本守恒；链路失败的样本不能提前进入目标数据分区。局部星簇先增加通信回放，原解析结果保留为基线并明确标签；不将单个有效带宽常数称为已实现动态网络。

启用方式建议 `communication.enabled=false` 默认兼容旧实验；新配置显式带 `schema_version`，未知或不支持字段报错而非静默忽略。网页/公网只选择注册策略 ID，不开放自定义 Python 路径或任意命令。

## 6. 实验设计与验收

### 6.1 三套实验族

| 实验族 | 控制与扫描 | 必报指标 |
| --- | --- | --- |
| 动态几何与同频共存 | 固定流量和射频预算；最高仰角/最长剩余窗口/干扰感知选星；开关合法同频源；扫描切换周期 | SINR/INR CDF、服务比例、门限超出率、切换次数、停机时长 |
| 外部干扰与抗扰 | 共享同一外生干扰轨迹；固定/随机/避扰策略；接收端 J/S 建议 −10、0、10、20 dB 压力档，扫描占空比 | 唯一载荷 goodput、交付率、重传、p50/p95时延、能量、换频/同步成本 |
| 多流资源竞争与 FL | TDMA-RR、TDMA-DRR、Slotted ALOHA 分组比较；扫描 offered load 0.25、0.5、0.75、1、1.5 倍无干扰单瓶颈容量 | 队列长度、溢出/超期率、Jain 公平性、每流等待、模型到达陈旧度、准确率-模拟秒、达到目标精度所需模拟时间 |

以上 J/S、负载档和起步规模均为设计假设，不从论文搬成工程事实。有限星簇可先 9/25/81 星；地面站数量、终端数量和流量必须配置固定，不能只改变卫星数而隐含增加总频谱。不能把 TDMA 与随机接入的差异直接归因为抗干扰算法收益。

每实验至少 5 个独立 seed，报告均值、标准差及置信区间和计算方法；重尾时延另报样本量和分位数。该数量是起步最低建议，不能保证统计显著。不同策略复用外生轨道、到达、天气和干扰轨迹；解码随机数按包/尝试等稳定键生成，避免因事件调用顺序不同破坏配对比较。响应式对手对不同策略产生不同响应，应固定对手规则并单列实验。

必须有消融：无干扰、仅动态速率、仅竞争、两者同时；再分别加入换频、功控、绕行，至少单列“忽略换频/感知开销”的理想上界与“实际计费”的版本。训练算法、初始权重和数据划分保持一致；同轮次准确率与同通信时间准确率分开报告。

### 6.2 最低验收门槛

1. 单位与量级：dBW/dBm 转换正确；相同频率距离加倍，FSPL 增加约 6.0206 dB；35,786 km 单程传播下界约 119.37 ms；额外非负干扰在固定其他条件下不能提高 SINR。
2. 资源守恒：任何时间区间的带宽、功率、终端并发不超预算；传输服务量不超过其实际可用区间速率积分，空队列不能发送；每个资源粒度的上界和整星汇总预算都要检查。
3. 包/消息守恒：唯一载荷的生成、在途、排队、已交付和终态丢弃可核对；重传不重复交付；掉线、超期和全干扰时不生成虚假聚合事件。
4. 协议验证：理想 Slotted ALOHA、泊松独立尝试且无捕获时吞吐符合 `S=G exp(-G)`，峰值约 1/e packet/slot。有限重传队列实验要单列，不能无条件要求满足该解析模型。后续 CRDSA 用 [6] 的配置与统计置信区间验证趋势和稳定性。
5. 因果与可重复：禁用未来观测、同 seed/快照/代码版本得到同轨迹；策略不访问引擎真值；按事件稳定排序。
6. 端到端：至少一次真实小模型训练，故意造成上传跨窗口、中断与重传，确认权重到达时间和服务器聚合时间一致；全部上传失败时显式记录无有效更新。
7. 数值收敛：建议先将几何步长减半，预先约定平均 goodput/时延变化 5% 作为工程筛查门槛，并检查事件边界；该 5% 不等于物理模型准确度或论文复现误差。

## 7. 页面与实施顺序

网页提供“通信场景”配置、“链路与队列回放”和“结果对照”。图上区分候选可见链路、已分配链路、发送中链路、干扰导致失败的链路；点击显示距离、SINR、分配带宽、队列和阻塞原因。线条动画由事件轨迹驱动。结果下载包含完整来源与参数，状态明确标注“通信仿真”或“真实 FL + 通信仿真”。

按以下顺序落地，每阶段通过后再增加复杂性：

1. **动态 RF 与事件内核**：单链路、视线、时变预算、传播、消息完成和记录；对照固定速率基线。
2. **共享资源与竞争**：终端约束、TDMA-RR/DRR、队列、Slotted ALOHA 和 ACK/重传；复现理论基线。
3. **干扰与可解释防御**：合法干扰、固定/扫频/Markov 干扰，带成本的避扰和换星；输出消融。
4. **FL 联动**：实际消息大小和到达驱动聚合，比较同模拟时间下的训练结果。
5. **研究扩展**：VDN/DQN、CRDSA/IRSA、经校准光学扰动、外部仿真交叉验证。

项目可验证的创新方向是“利用剩余接触窗口、队列、干扰观测与更新陈旧度联合调度，优化单位通信时间的有效聚合收益”。这目前是研究假设；只有在相同资源、可复现对照与多 seed 实验下取得结果后，才能报告收益。
