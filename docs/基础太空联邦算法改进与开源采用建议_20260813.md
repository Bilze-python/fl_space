# 基础太空联邦算法改进与开源采用建议

## 当前采用结论

第一阶段不直接替换现有算法后端。原因是 SpaceFL 已经具备轨道仿真、接触矩阵、离散时间模型、三种算法组件和网页 Session 参数链，直接替换会丢失最关键的轨道语义，也会破坏现有实验档案兼容性。

本轮采用“核心算法本地可审计 + 通用框架作为可选执行层”的结构：

- `FedAvgSat / FedProxSat / FedBuffSat` 的论文近似协议继续由 `fl_space.fl` 实现，便于逐行对应论文伪代码和记录调度证据。
- 项目已有 `fl_space.integrations.flower.FlowerAdapter`，能把 `ContactMatrix`、地面站接触窗口和 ISL 窗口转换为 Flower 可消费的查询接口。Flower 适合后续承载真实多进程/多节点执行，但当前适配器还不是完整 Flower Strategy/ClientApp 集成。
- `flwrlabs/femnist` 已被数据加载器作为 FEMNIST 来源使用，适合复现 `2511.14889v1` 的 writer-level non-IID 数据，但正式比赛实验仍需固定数据版本、writer 列表和哈希。
- 代码中记录的 `teleportup/FedLEO-Federated-Learning` 被项目自身标注为中心化地面站 FedAvg，不是 Zhai 2024 的卸载式去中心化 FedLEO，因此不接入核心算法。

## 本轮已落地的论文近似能力

### FedAvgSat

- 新增 `EarliestReturnSelector`。
- 服务器根据首次模型下载接触、本地训练估算和后续上传接触计算预计完成时刻。
- 论文近似模式按预计返回时刻选择前 C 个卫星，并在事件中保留下载、训练、上传和到达时间。

### FedProxSat

- 保留标准 FedProx proximal 目标。
- 论文近似模式将本地 epoch 预算绑定到下一段接触窗口起点，受网页可调的最大 epoch 限制。
- 每次更新记录实际执行 epoch 数。

### FedBuffSat

- 异步本地训练器新增可调 proximal 系数。
- 缓冲聚合器新增最大 staleness 硬边界，超限更新被丢弃并计数。
- 保留原有 FIFO 缓冲、版本化 delta、陈旧度降权和 server learning rate。

### 单星数据画像

每颗卫星可单独设置：

- `preferred_classes`：偏好类别数组；
- `preference_probability`：该类别进入偏好卫星集合的概率；
- `max_samples`：该卫星独立样本上限，0 表示不额外限制。

实际标签分布继续随训练结果导出，可用于检查网页设定是否被真实消费。

FEMNIST 保持论文的 writer-level 身份，不按类别重新路由样本；此时单星画像只应用 `max_samples`。这是为了避免一边打散 writer 数据、一边错误声称使用自然 non-IID FEMNIST。

## 尚未完成的开源核验

2026-08-13 本次检索时 GitHub 网页、GitHub API 和搜索服务均连接超时，因此没有把任何未知仓库的许可证或实现范围标记为“已核验”。后续联网恢复后，候选项目必须至少满足以下准入条件：

1. 仓库中存在明确许可证文件，且允许修改与再分发；
2. 能定位到对应算法伪代码的实际训练、聚合和调度实现，不接受只有论文脚本或结果文件；
3. 可固定依赖版本、随机种子和数据索引；
4. 接入后不绕过 SpaceFL 的轨道接触、时间模型和实验事件记录；
5. 通过与本地实现相同的契约、同数据和同初始权重交叉验证。

## 下一阶段建议

1. 将 `FlowerAdapter` 补成真正的 Flower Strategy/ClientApp 执行后端，保留当前单进程模拟器作为确定性参考实现。
2. 为 `paper_approx` 建立 FEMNIST、90° Walker-Star、3 个月窗口和 5 seeds 的固定实验模板。
3. 增加“集中测试集 + 轨道可接触评估客户端”双评估协议。
4. 对三算法输出同预算对比：客户端更新数、服务器更新数、轨道时间、通信字节数和准确率，不再只按轮数比较。
