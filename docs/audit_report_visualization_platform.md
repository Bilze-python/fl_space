## A. 物理与工程规范问题

### A1. 🔴 严重 — 实时WebSocket推送与时间模型冲突

**位置**: 设计方案 §3.3 实验管理 WebSocket事件

**问题描述**:
设计方案中的实时事件推送：
```json
{"type": "round", "round": 5, "total": 20, "accuracy": 0.6224, "timeslot": 14}
```

存在以下物理一致性风险：

1. **时间模型混乱**: 现有系统支持 `slot` 和 `physics` 两种时间模型（见 `fl_space/fl/time_model.py`），WebSocket推送的 `timeslot` 值必须明确其含义：
   - 是虚拟时隙编号（离散）？
   - 还是物理秒级时间戳（连续）？
   - 如何处理 `physics` 模型下的亚时隙级精度？

2. **轨道状态不同步**: 训练轮次与轨道时隙的映射关系在 `FLServer.run_sync` 中是**通信窗口驱动**的（见 `dev_discussion_2026-06-01_02.md` §2）。WebSocket推送必须同步以下状态：
   ```python
   {
       "round": 5,
       "timeslot_start": 14,  # 本轮开始时隙
       "timeslot_end": 27,  # 本轮结束时隙（含训练+传输）
       "orbital_config": "...",  # 当前轨道配置快照
       "time_model": "slot",  # 使用的时间模型
       "time_breakdown": {...},  # TimeBreakdown对象
   }
   ```

3. **3D视图时间不连贯**: 若用户在3D Cesium视图中拖动时隙滑块到第20时隙，但训练实际运行到第14时隙，两者状态会发散。
