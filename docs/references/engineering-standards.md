# 航天卫星扩展工程规范

## 分层

依赖方向保持为：

```text
config → environment/orbit → simulator → FL
                              ↑
                         mission
```

`mission` 是任务编排和领域模型层，可以调用 `environment` / `orbit`；
`orbit` 和 `fl` 不得反向依赖 `mission`。

## 数据模型

- 配置、任务状态和外部数据转换对象使用 `@dataclass`；
- 公共对象提供 `to_dict()` / `from_dict()`；
- 可变默认值使用 `field(default_factory=...)`；
- 构造时验证范围，不把无效值推迟到模拟中途；
- 物理参数和渲染参数分开；
- 外部 API 原始字段不要直接泄漏成核心模型字段。

## API 与插件

- 公共 API 从包的 `__init__.py` 显式导出并维护 `__all__`；
- 新卫星、任务模式和经营规则优先通过注册表或插件目录扩展；
- 插件不得覆盖核心文件；
- 外部服务使用适配器，不把网络客户端放进核心物理模块；
- 读写外部数据时保留来源、快照时间和保真度标签。

## 代码

- Python 3.9+；
- 标识符使用英文，中文注释和 NumPy/SciPy 风格 docstring；
- 使用 Ruff，配置见根目录 `pyproject.toml`；
- 新物理公式写出单位、假设和适用范围；
- 随机过程必须接受显式 seed；
- 不使用“魔法数字”隐藏任务规则，使用带单位的常量或配置字段。

## 测试

新模块至少覆盖：

- 正常创建和序列化往返；
- 一个量级检查；
- 一个无效输入；
- 与现有 `KeplerOrbit` 或模拟器的最小集成；
- 插件/注册表的注册、获取和移除。

涉及轨道、通信或推进的结果，要同时记录：

- 配置；
- 单位；
- 后端/保真度；
- seed；
- 输出路径；
- 与真实数据的来源或假设。
